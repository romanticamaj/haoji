# 好記 Haoji — MVP 討論與決策紀錄

捕捉 office-hours + MVP brainstorm 的重點,作為設計依據。日期：2026-06-27。

## 從哪裡來

先前在 `multi-speaker-extractor`(本機 web 工具)做了 POC,驗證了：
- ASR + 講者分離(Breeze ASR,聯發科台灣模型)可產出繁中逐字稿
- 本機 LLM(Ollama `gemma4:e4b-it-qat`)能把逐字稿整理成結構完整的繁中會議記錄(摘要/重點/決議/待辦)
- 拖曳上傳、複製/匯出、講者命名都跑通

POC 過了 → 決定做第一版 MVP「好記 Haoji」。

## 楔子(office-hours 收斂)

會議記錄 AI 賽道很擠(Otter、Fireflies、Granola、tl;dv、Fathom、Notion AI;中文有飛書妙記、通義聽悟),但好記有三個它們較弱的點：

1. **繁體中文 / 台灣準確度** — 大廠英文優先,繁中口音與專有名詞常錯。好記 ASR 用 Breeze、會議記錄繁中生成 + OpenCC s2tw。
2. **不綁帳號、不留資料** — 一次性需求不想註冊;敏感會議不想丟雲端 SaaS。
3. **死簡單 UX** — 一顆大紅錄音鍵。

> 重要提醒(來自討論中被打臉的點):隱私定位不能講「音檔不出手機」,因為分析要送後端 = 對使用者來說也是雲。誠實版是「不綁帳號、不留音檔、結果存你手機」。

## 關鍵決策

| 決策 | 結論 | 理由 |
|---|---|---|
| 產品名 | **好記 Haoji** | 繁中、好記、雙關(好+記/容易記住);主打台灣市場 |
| 主打市場 | 繁體中文 / 台灣 | 這是真正的護城河,大廠最弱處 |
| 平台 | 原生 App(iOS/Android) | 使用者要「手機上看、超簡單錄音鍵」 |
| 技術棧 | Expo / React Native | 單人跨平台最快;錄音/本機儲存/IAP 都成熟 |
| 帳號 | 不綁帳號 | 降低門檻;結果存本機 |
| 後端 | 沿用已驗證 pipeline,包成 mobile API | 不重造輪子;先本機,之後上雲 scale |
| LLM | provider 抽象層,Ollama gemma4 預設 | 可切換;預設模型隱藏,下拉可換 |
| 付費模式 | 預覽 + 解鎖完整 | 看到價值再付,轉換較高 |
| 金流 | IAP(RevenueCat),**非** Apple Pay/Line Pay | iOS 數位內容強制 IAP,否則退件 |
| 定價 | 初始 NT$60/份(可調) | 上線後依轉換調整 |

## 規格重點(使用者原話整理)

- 不綁使用者,結果存手機;可下載逐字檔、會議記錄;手機上看會議結果。
- UI:一個大大的紅色圓圈「錄音鍵」+ 當前訊號顯示;支援中斷/繼續錄音;或直接上傳音檔/錄影分析。
- 分析送後端(先本機小服務,記下來,之後上雲 scale)。
- 分析後看逐字稿,可調 speaker 名稱 → 進 LLM 分析 → 看結果 → 複製/輸出。
- 結束錄音就大大的「分析」兩個字。
- 結果頁可切換不同分析結果/中間過程;一切留在使用者端。
- UI 超級超級簡單。

## UI 方向

見 `design/moodboard/`(使用者提供):白底 + 紅色重點色、iOS 原生、極簡、大量留白。錄音流 + 結果流(Tab 切逐字稿/AI 分析)。

## 不做(YAGNI)

帳號、雲端同步、即時逐字稿、協作/分享、背景錄音、自訂 prompt/人格 — 都留待 MVP 之後。
