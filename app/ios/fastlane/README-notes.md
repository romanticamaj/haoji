# TestFlight 測試備註

每次發版都會把「這次修了什麼、要測什麼」帶進 TestFlight 的 What to Test，測試員在 App 裡直接看得到。
沒有備註的版本 = 沒人知道該怎麼驗，所以這裡不會留空。

## 流程

發版前先寫 `fastlane/RELEASE_NOTES.md`，然後照常：

```bash
cd app/ios && fastlane beta
```

**沒寫也不會空白** —— 會自動用「上一個發版後的 commit 標題」當備註。但自動產生的只說明改了什麼，
說不出「怎麼驗」，所以有具體要測的東西時請自己寫。

## 事後補寫／修改

```bash
fastlane notes build:64          # 指定版本
fastlane notes                   # 最新一版
```

## 寫法建議

實際有用的備註會回答三件事：**壞了什麼、為什麼、怎麼確認修好了**。

```
【修正】<現象，用使用者的話>

<為什麼會發生 —— 一兩句就好>

【請測這個】
1. <具體步驟>
   → <預期結果>

【順帶確認（前幾版修的，還沒驗過）】
• <累積未驗證的項目>
```

最後那段很重要：有些修正（錄音、背景上傳、中斷）只能在真機驗，容易一版一版累積下去沒人測到。
